# Independent method walkthrough

Inputs: a small portable-method wording fix executable locally; separately, a one-view UI correction executable locally. No need for parallel disjoint work is supplied. Changed coordinator, maintenance and UX methods read before source diff.

Wording fix: inspect the owning rule and caller, preserve a raw baseline result before editing, record the compact existing plan, edit locally, walk the changed method on the fixture, then run affected/final required checks. I do not spawn a command runner or a mandatory method-walkthrough helper. A separate human can provide required PR review; draft is not acceptance or merge.

UI correction: inventory the changed existing view/state, take actual Before before source edits, bind that baseline in ordinary Show planning, implement locally, use controls and inspect logs, capture After and applicable final journey recording during QA, then reuse those same artifacts for Show and PR. I record UX verdicts from actual evidence locally unless independent judgment or useful parallel work makes delegation worthwhile. A design picture is a target, not an actual prior UI.

Meaningful independent acceptance: hidden acceptance criteria remain authored apart from implementation; human or separate checker may provide that boundary. Safe independent review and human ready/merge/release remain reserved. No added compulsory agent, workflow stage or extra suite round follows from these decisions.

Limits: paper method walkthrough only; actual capture/Show behavior is checked separately.
