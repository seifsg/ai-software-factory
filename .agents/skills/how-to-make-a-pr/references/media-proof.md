# Visual and journey proof

Every PR shows a skeptical owner truthful before/after proof: what failed or was missing, what now works, observed benefit. Required in every mode. Short schema, diagram, table or labeled emoji may explain nonvisual proof.

1. **Inventory now:** map ticket/diff to changed views, states, journeys, including shared-logic effects. Primary platform only, light (existing app: its lead; else web = desktop, mobile app = phone). Secondary platform, themes: after owner confirms primary, or on request. One outcome per journey; share pairs/clips with chapters across outcomes. Reconcile final diff. Same rendered state: behavioral checks, not duplicate pictures. Unchanged views/speculative cases: no media unless required.
2. **Capture each Before now**, minimum safe navigation. Exercise or side effects needed: isolated fixture or existing evidence, conditions stated. Where tool allows: scroll with `behavior: 'instant'`, discard one warm-up shot, click by element ref not coordinates. Missed: SKILL.md step 4. Never fabricate it, reset dirty work, or start a second checkout or server to recreate it.
3. **Prepare the demo:** isolate workspace/profile; use safe deterministic fixtures and reset recipe. Preserve owner data; match viewport/theme/state/data/workload/framing or explain differences. Focus on changes; extra full-page shots need a reason. Design likeness supplements actual Before/After. Preflight capture/playback and authorized upload with first planned artifact; keep complete command, session and exit output. Pending or missing results block dependent proof; never invent an upload or install.
4. **Capture each After during final manual QA**, per table: each journey from entry, single-step flows included, through real controls to confirmed result, plus relevant changed validation, failure, edge, recovery paths. A success toast alone proves no external result. Use authorized test destinations; recording grants no sending permission.

| Surface | Proof, Before and After |
|---|---|
| Screen, page, section | Screenshot pair per changed view and distinct visual state; no hero image standing in for the rest |
| Touched interactive journey, motion | Screenshot pairs for each step that changed; a video only when the owner asks or a still cannot show it |
| New visual surface | Before: "did not exist", no capture; After: new screenshot |

- **Bug during capture:** stop, keep short sanitized failure note, fix in scope, run affected checks, commit and push checked fix if authorized, reset fixture, then restart whole planned demo on that candidate. Replace failed or stale After media; never edit a failure out to imply success. Fix needing new authority blocks demo with cause and next action; no silent deferral or clean-pass claim.
- **Keep it fast:** plan routes once; reuse build/fixtures; screenshot during QA recording; share clips; batch uploads/body updates. No duplicate angles. Record setup/capture/upload durations and slow stage; explain material delay in PR. Shortest complete demo; never drop required coverage for time.
- Inspect every screenshot, play every clip: readable, correct, no unexplained errors/secrets. Reuse same-candidate/state/input observations and URLs with provenance/access checked. Changed/unknown inputs invalidate affected After; source drift still needs fresh verify pass, including docs/tests. Never restamp stale media. Keep Before and unmatched conditions; a demo cannot rule out bugs.
- Upload first (`github.md`); verify every image renders/video plays for reviewers in PR. No localhost/local links; inaccessible media = missing proof.
- **Media waiver:** needs explicit scoped owner authority; never the answer to a host that cannot save images (use `pane:` observations); tools/access/time imply none. Missing media stays visible gap with recovery action and blocks evidence completion. Incomplete draft preserves progress, not a completed handoff.
