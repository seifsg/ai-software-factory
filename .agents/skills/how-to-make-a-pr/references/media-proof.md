# Visual and journey proof

Every mode shows observed Before/After per outcome. Illustrations and prose explain results but never replace them. Shared backend changes demonstrate affected UI journeys.

1. **Inventory before editing:** map ticket/diff to changed views, distinct states and journeys. POC/MVP: light desktop; mobile apps: light phone. Extra themes/devices/responsiveness need a cited request or requirement. Preserve design coverage; reconcile the final diff. Identical rendered states need behavioral coverage, not duplicate images; unchanged/speculative views need no media unless required.
2. **Capture Before now:** minimal safe navigation; isolate side effects or cite existing evidence and conditions. Web: `shots --phase before`; final QA uses `--phase after` with that baseline. `--base` is disclosed reconstruction, never pre-edit capture. Missing Before remains a gap; never fabricate it or reset dirty work.
3. **Prepare:** isolated workspace/profile, safe deterministic data and reset recipe. Match viewport/theme/state/data/workload/framing or explain differences. Design likeness supplements actual Before/After. Extra full-page angles need a reason. Preflight capture, playback and authorized upload with the first artifact; retain command/session/exit receipts. Pending/missing results block consumers. No invented upload/install.
4. **Capture After during final manual QA:** entry through real controls to confirmed result, including changed validation, failure, edge and recovery paths. Include single-step journeys. A toast proves no external result. Authorized test destinations only; recording grants no sending authority.

| Changed surface | Required proof |
|---|---|
| Screen/page/section | Screenshot pair per changed view and distinct state; no hero-only substitute |
| Interactive journey/motion | Final-candidate video per journey plus its changed screenshot pairs; Before video optional |
| New visual surface | Prior entry/empty state labeled "did not exist", then new screenshot |

- Capture bug: preserve a sanitized failure note, fix in scope, run affected checks, commit/push when authorized, reset and restart the planned demo on that candidate. Replace stale/failed After; never edit a failure into apparent success. New authority blocks its dependent demo with cause/next action.
- Plan routes once; reuse builds/fixtures, capture screenshots during QA recording, share clips with chapters and batch uploads/body edits. No duplicate angles or skipped required coverage. Record setup/capture/upload times and explain material delay in the PR.
- Inspect every picture/play every clip: correct, readable, no unexplained errors/secrets. Carry observations/URLs only with verified relevant-input identity, intact evidence, original provenance and access. Explicit nonvisual exceptions need dependency evidence; file extensions prove nothing. Changed/unknown inputs invalidate affected After. Keep early Before; never restamp old captures as new. Whole-candidate checks remain strict.
- Upload first ([sharing](github.md)); confirm reviewer-visible rendering/playback. Localhost/local links or inaccessible media are missing proof.
- Outcomes declare Visual/Journey ([layout](pr-layout.md)). Waivers need explicit scoped owner authority; time/tools/access imply none. Missing media blocks evidence completion with its recovery action. An incomplete draft preserves progress, not a completed handoff.
