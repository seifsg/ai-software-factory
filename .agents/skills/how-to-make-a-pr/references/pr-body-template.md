# PR body template

Use the original's **PR-Beschreibungsstil — visuell zuerst** section in [How to make a PR](../SKILL.md). It contains the section order and the blocks to copy.

Read the target repository's PR template first. Fill it with the original's required context, attribution, Why, before/after, checks and handoff. Use the actual [project bindings](project-bindings.md).

Ticketed work: refresh the canonical ticket before submission. Link its original input, latest confirmed scope revision/digest and owner source; preserve changes/reasons in Adjustment History. In the existing verification section, map each confirmed criterion to the actual change/journey, exact-candidate proof and gaps. Include dependencies/integration status and accessible before/after evidence. [Comparison](../../../../docs/pr-workflow.md#compare-the-current-ticket).

Pending scope, drift or failed refresh is an open dependent step. A draft, local PASS or old plan never replaces the owner's current expectation.
