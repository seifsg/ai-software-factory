# Worth-it repair rounds

Use `deep-review`'s worth-it assessment for every review or check finding. Keep required quality and owner authority; optional polish may wait in the existing epic follow-ups ticket.

1. Keep the complete report in JSON: `findings` is a list; each has `location`, plain `description`, `severity`, `disposition`, `exception` and `worth`. A clean report has an empty list.
2. `worth` holds `notice` (0..2), `harm` (0..3), `minutes` (whole nonnegative estimate or null), `required` (boolean), `reason` (one line). Cost points are 2 under 15 minutes, 1 under 60, else 0; score is notice + harm + cost. Null cost stays unknown.
3. Required work, harm 3, HIGH/CRITICAL, blocking findings and missing/challenged proof are mandatory. Optional score >=5, or 3..4 under an hour: do now. Other optional work waits for Finishing touches. Estimate unknown optional cost before a fix round.
4. Park only with actual owner authority, reason, scope, revisit condition and `destination` in `exception`; use the epic's one existing follow-ups ticket. Do not treat a low score as consent or mark missing requirements done.
5. Before each repair round, run `fast_gate.py fix-round --project <abs> --file <report.json> --finding F1 [--finding F2]`. IDs follow report order. The gate rejects optional low-value selections even beside required fixes, and reopens build when accepted. Preserve its receipt.
6. For an explicitly requested finishing batch add `--finishing-authority "<owner instruction and source>"`. Select its whole agreed scope once; finish the batch, use it, then run one final test pass for that candidate. A failure or changed input needs repair and fresh affected proof. Only the owner cancels it.
7. At done-run record `**Findings:** none` only when no repair round occurred and checks are clean; otherwise name the final scored JSON path. Reconcile every prior receipt finding, selected or not, once by `report_sha256` and `finding`: `retained` also names `current_finding` with unchanged content; `resolved` adds actual `evidence`; `cancelled` adds `owner`, `authority` (instruction and source), `reason`. Any receipt selection needs resolution or owner cancellation to complete; Safe FAIL may retain it. Retained findings keep their duties; cancellation cannot waive remaining criteria. Never invent resolution proof. Show parked facts plainly, links separate.

Safe uses the same assessment: `repair --finding F1` selects from its intact recorded review; before review or after a clean review add `--findings <report.json>`. `--finishing-authority` has the same meaning. Existing saved runs keep their prior validation; new complete-cycle runs require scores. A declaration records authority, it cannot authenticate its author.
