# Preserve Seif's complete working method

Use on initial load, after context loss, on resume and when handing work to another instance. This table routes to canonical instructions; it never replaces reading them. No file is imported merely to reserve a future skill name.

| When | Full instruction to load | Evidence carried forward |

The planning comparison is part of the coordinator and original PR-review method; there is no invented separate recommendations skill. Preserve an existing user decision instead of asking for it again. A reviewer follows the [session contract](session-contract.md): delegated choices can proceed; reserved choices remain with Seif. Review-only authority remains read-only.

## Resume and delegation packet

Pass the original request verbatim, acceptance criteria, session contract (delegated/reserved decisions, handoff/checkpoints and actual constraints), approved/rejected/unresolved decisions, original plan and research/revision artifacts when applicable, task/profile and saved phase, project path/worktree, base/head/current diff, canonical skill paths, recorded analysis/plan/batch/improvement, command logs and review results, freshness state, diagnostic correction history, demonstrated progress and actual obstacles, and PR/task links when present. The receiver reads `status`, the current instructions and actual code, then resumes the first unfinished/invalidated step. Do not initialize again, invent missing artifacts or accept stale evidence.

In each existing stage artifact, state which full routines/references were read and point to the actual outputs. For a PR, put the same evidence in the detailed review comment. No additional controller command or fabricated receipt is implied. The controller validates ordering and input integrity; its independent reviewer assesses method substance. Host-level automatic injection and universal enforcement are not implemented.
