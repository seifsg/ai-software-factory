# Hidden checks: select, author, execute

Read for a new run's proof plan or independent checker handoff. Old runs keep their recorded contract; the sealed controller keeps its configured checks.

1. Before plan, record `checks --plan <json>`: every listed ticket's full pasted body, category and reason. Other trackers retain the existing offline/unverified path. At done plan, freeze which epic integration criteria this run owes from its todos; the owning run keeps the later proof. Pure appearance/layout ports default to no hidden checks; retain frozen coverage, fresh independent likeness and the declared suite. Logic, data, safety and mixed tickets require hidden checks. Adding them to a visual-only port needs the owner's request/source. Priority never waives proof.
2. Use an independent checker before its build wave; a human or separate context suffices. Give it the pasted issue text, Interface, Ports and applicable UX rules. It reads named committed interface files, never implementation. It writes one executable or specific manual procedure per selected criterion; the builder never opens those files. No guessed names. New runtime names unavailable before build stay explicitly pending.
3. The checker calls `checks --prepare <json>` after every edit. The gate parses declared source files; only a syntax-ready set releases authoring readiness. This is not a product pass and does not require a finished build. Unsupported syntax needs the project's real tool and a written manual check, never an invented parser success.
4. Finish implementation and manual use; UI also completes Show. Capture actual runtime accessible names, with candidate, viewport/state and source, then record `checks --runtime <json>`. Give that snapshot to the checker and finalize its selectors. Non-UI checks record why names do not apply. A path alone proves neither capture nor actual names; inspect the raw snapshot.
5. The independent checker runs `checks --run` on the build. It re-parses before execution. Manual procedures use `checks --observe <json>` with actual observation, observer/source and candidate. An owner/hardware-only check records the existing DEFERRED reason; everything else gets checked. Retain syntax, setup, execution and interruption failures. A nonzero result is failed/unclassified until inspected, never automatically a product defect or harness mistake.
6. The checker returns one `#<n> <ID>: PASS|FAIL|DEFERRED (owner|hardware: reason)` entry per selected criterion, or `<ticket URL>#<ID>: ...` when the tracker lacks an issue number or numbers collide. Notes follow only afterward in parentheses. Only a checker that has not seen implementation may repair a demonstrably wrong check, recording why. Any change invalidates its proof. The coordinator copies verdicts unchanged under `**Hidden checks:**`; any FAIL returns to build.
7. Completion checks current source, files, argv, declared environment, executable and logs. It still needs explicit criterion verdicts. Syntax-only, unrun, changed or failed sets cannot pass. Visual-only work cannot omit both hidden checks and likeness/suite proof. Refresh the ticket contract; changed requirements need a newly confirmed plan, not an edited receipt.

Artifacts stay ignored. Do not put private issue bodies, snapshots or environment values in commits. Record only hashed environment inputs. The gate observes commands and identities; it does not authenticate humans, prove checker independence or sandbox arbitrary commands. The coordinator verifies those boundaries.

Browser checks: use [the runtime helper](playwright.md) for duplicated controls, focus-only links, alpha backgrounds and masks. These are observations for explicit assertions, not automatic visual signoff.
