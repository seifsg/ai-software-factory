# Select independent proof

Old runs retain their contract; Safe retains its sealed controller. Reuse existing criterion coverage instead of creating duplicate tests.

1. Before plan, checks --plan records listed ticket bodies/category/reason. Freeze this run's owed epic criteria from its todos; later integration proof stays with its owning run. Covered simple logic may use hidden:false with a reason naming existing tests; completion requires current passing planned validation. Data/safety/mixed or uncovered behavior retains hidden checks. Visual-only ports retain frozen coverage, independent likeness and planned validation; adding hidden checks needs owner request/source. Priority waives nothing.
2. For selected hidden checks, an independent human/separate context gets ticket, Interface/Ports and UX rules. Read named committed interfaces, never implementation; write one executable or specific manual procedure per criterion. Builder never reads assertions. Missing runtime names remain pending, never guessed.
3. checks --prepare validates syntax before authoring readiness; repeat only after editing checks. Syntax is not a product pass. Unsupported syntax needs the real tool plus a written manual check.
4. After implementation/manual use and UI Show, checks --runtime binds actual accessible names, candidate, viewport/state and source. Inspect raw capture, finalize selectors; non-UI says why names do not apply.
5. Run checks --run once on the build; manual checks use checks --observe with actual observation/source/candidate. Only owner/hardware-only work may use the existing DEFERRED reason. Retain syntax/setup/execution/interruption failures; nonzero needs diagnosis, not automatic blame.
6. Return each selected criterion as #2 A1: PASS|FAIL|DEFERRED (owner|hardware: reason), or <ticket URL>#A1 for other trackers/collisions; notes follow in parentheses. Coordinator copies unchanged under **Hidden checks:**. FAIL returns to build. Only an implementation-blind checker may repair a demonstrably wrong check with a reason; changes invalidate proof.
7. Completion binds current source/files/argv/environment/executable/logs and explicit verdicts; syntax-only, unrun, changed or failed proof cannot pass. Refresh ticket requirements; drift needs a confirmed plan, never edited receipts. Other trackers retain offline/unverified behavior.

Keep artifacts ignored, private bodies/snapshots/environment values out of Git; hash values. The gate cannot authenticate observers/owner authority, prove independence or sandbox commands. Coordinator verifies those boundaries. Browser edge cases use [runtime helper](playwright.md), not automatic visual signoff.
