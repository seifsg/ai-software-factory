# Hosts

Contents: first-class hosts · delegation · other agents · portable review evidence · sources

Methods are host-neutral. This page = what differs per agent: where skills live, how a step loads its skill fresh, how hooks are wired, how delegates get their model.

Backed lines and messages with none passed 18 of 18; a backed line with no `may stop` went to the check 9 of 12, the other 3 ended the turn. The run audit checks each gate line's backing: fresh reviewers flagged a swapped checker id, a forged cap and a forged waiver, 1 run each, and passed a real run. Not tested: a forged line citing a real checker's PASS on other work; Opus; Fast mode in a real run. Hooks run the `factory` binary (crate `factory/`) through `.agents/scripts/factory.cmd`, one LF launcher that both `sh` (macOS, Linux, Git Bash) and `cmd.exe` read; it starts `scripts/factory-<target>` for the machine (x86_64 or aarch64; Windows msvc, macOS, Linux musl). No Git Bash and no `git` alias. Codex: `command` (sh) and `commandWindows` (`cmd.exe /d /c call`, so PowerShell or cmd both work); Cursor: `hooks/cursor.json`, an unquoted `${CLAUDE_PLUGIN_ROOT}/scripts/factory.cmd` (its one `command` runs in PowerShell on Windows and in `sh` elsewhere, and a quoted path cannot start a PowerShell command, so a plugin path with spaces breaks it; Stop hooks run from the workspace root; not yet run live). A checkout with no binaries (development) falls back to the sh scripts on `sh` hosts and says so on `cmd`. The binary keeps the sh guard's replies and state bytes (`factory/parity/run.sh` diffs both), reads refs, config and objects natively (no `git` process), and reads transcripts from saved byte offsets (`.factory/guard/scan`). Finds the run in order: the session file `${XDG_CACHE_HOME:-~/.cache}/ai-software-factory/sessions/<session id>`, nearest `.factory/run.md` inside session's checkout (walking up from the hook input's `cwd`, else the hook's own directory: a desktop worktree session's hook may start elsewhere), then the `**Workspace:**` path of a step block opening the turn's last message. A step block naming a run rebinds first. A desktop worktree session cannot change folder, so its run often lives elsewhere; a step block with no findable run blocks once and asks, then warns the owner. A stopped or finished run deletes its session file; files over 30 days go at the next bind. A worktree's run stays separate from its parent's. Also reads that session's subagent files and, on Claude Code, the run's session transcripts (posted step blocks). State: `.factory/guard/state` (single-quoted `g_*` lines; anything else reported and ignored). Ignores runs untouched for 12 hours. Only `Waiting: owner:` or `jobs:` stops a run; any other spelling is driven and told the exact header. Gate C and final review lines count only with a passing full-suite receipt for the tree of their commit (`.factory/receipts/<tree>-full.txt`, written by `factory receipt run --suite full -- <command>`, which reuses a PASS already on that tree; format: [receipts](receipts.md)); Gate C only with one that counts a single passing run, and any second run on one tree is flagged once. A step 5 block or `T<n> pre:` line, posted or written with `factory guard step`, is refused while a proof-list id (`**Proof list:**` in `## 3 Plan`: a table row's first cell or a bullet's first word, holding a digit like `P1`) has no `before-<id>` file in its proof folder (`.factory/proof/<ticket>/` when the `# Run:` line opens with a ticket link or `#<n>`, even before it exists; else all of `.factory/proof/`; a new surface's file says `did not exist`), or one saved after the branch's first source change: its first commit after the base (`origin/HEAD`, else `origin/main` or `master`, else `main` or `master`), or its oldest uncommitted change newer than the commit where it left that base (`git status`; a deleted file counts by its folder's time). The refusal names the folder it read and what began the work. A new project needs no Befores: base commit with no files, and no commit or uncommitted change older than the ticket step (`.factory/guard/steps.jsonl`). `factory review gate-a` names a Proof-list line that opens with no id. A pass is kept in `.factory/guard/before` until a Before changes. The sh fallback checks neither Befores nor receipts. Past step 3 it names a step not ticked; at any step it refuses a run file line over 300 characters outside tables and fences; neither finishes. A finish it saw holds while the run says `Status: closed`, wherever HEAD went; `closed` alone proves nothing. No remote, ever: `HEAD` counts as pushed. Paths reach the agent in `C:/x` form. Runs once per turn end, never per tool call. `night.sh` and `watchdog.sh` in `tools/night/` call the host CLIs above; `FACTORY_CLAUDE` and `FACTORY_CODEX` name a CLI off PATH (desktop installs), `FACTORY_START`, `FACTORY_RESUME`, `FACTORY_FRESH` and `FACTORY_NOTIFY` replace the commands, `FACTORY_IDLE_TURNS` (6) and `FACTORY_JOB_MAX` (120 min) tune the guard. Git Bash rewrites `<ref>:<path>` arguments (`git show <base>:<path>`) into Windows path lists: prefix that command with `MSYS_NO_PATHCONV=1`, in the agent's shell and in hook commands; never set it globally, which breaks POSIX path arguments ([install](install.md)).

### Native Codex initialization

Resolve `factory` on PATH first. Otherwise use the packaged `<plugin root>/scripts/factory.cmd`: PowerShell `& "<plugin root>/scripts/factory.cmd" ...`, or POSIX `sh "<plugin root>/scripts/factory.cmd" ...`.

After creating the run header, run `factory guard begin` in its worktree before Ticket work. It binds `CODEX_THREAD_ID`, falling back to `CODEX_SESSION_ID`, to the exact verified rollout under `CODEX_HOME/sessions` (default `~/.codex/sessions`). This gives a child its own identity even when it inherits its parent's session variable. Missing or ambiguous metadata fails initialization explicitly.

The existing guard state and session route then let Stop and resume find this worktree from a parent chat cwd.

## Delegation

Roles (runner, analyst, maker, builder, reviewer, checker), their tiers and brief, gate and handback rules live in `.agents/skills/safe-factory/references/delegate.md`. Hosts differ only in how a role gets model, effort and edit limits. Owner's own session model and effort never change.

Pass request, decisions, interfaces, stops and artifact paths explicitly; full history needs a reason. Keep short jobs local.

| | Claude Code | Codex |
|---|---|---|
| Roles | plugin agents `safe-factory:<role>` from `.agents/agents/`; when missing, a general-purpose agent with the tier's `model` and `effort`, told to stay read-only where the role is | none shipped: the brief names its role |
| Tier models, light / standard / deep | `haiku` low / `sonnet` medium / `opus` high, pinned in each agent file | the spawn asks for effort `low` / `medium` / `high`; the model stays the parent's unless the owner sets one |
| Read-only roles | a `tools` allowlist without write tools; shell writes barred by instruction | by instruction only |
| Session ceiling | a role above the session's tier runs on the session's model | the parent's model, unless the owner sets one |
| Owner override | per-call `model` and `effort`; `CLAUDE_CODE_SUBAGENT_MODEL` with `CLAUDE_CODE_SUBAGENT_MODEL_FORCE=1`; `CLAUDE_CODE_EFFORT_LEVEL` | an agent file in `~/.codex/agents/` or `.codex/agents/` named for the role, with `model` and `model_reasoning_effort` |

## Worst-user roast

Step 6 runs `factory roast <app URL> .factory/proof/<ticket>/roast` in the background on web UI runs. It hands the running app to the other vendor's agent CLI, which plays the worst user in a headless browser and roasts the UI. Output: one line, `roast <cli> <SHIP|SHIP-WITH-FIXES|DO-NOT-SHIP|INCOMPLETE> <n> findings <s>s <path>/roast.md`, or `SKIP <reason>` (exit 0).

| Host | Roasts with | Command the binary runs (from a fresh temp folder, brief on stdin) |
|---|---|---|
| Claude Code (`CLAUDECODE=1`) | Codex, else Claude | `codex exec --ephemeral --skip-git-repo-check --ignore-user-config -s read-only --disable shell_tool --disable unified_exec --disable browser_use --disable computer_use --disable in_app_browser -c model_reasoning_effort=medium -c mcp_servers.pw.*=… -o agent.md -` |
| Codex (`CODEX_THREAD_ID`) | Claude, else Codex | `claude -p --model sonnet --restricted --settings settings.json --strict-mcp-config --mcp-config mcp.json --tools "" --allowedTools mcp__pw__… --permission-mode dontAsk --max-turns 80 --max-budget-usd 3 --output-format json` |
| Other or none | Codex, else Claude | as above |

- Browser: Playwright MCP `@playwright/mcp@0.0.86` through `npx`, `--headless --isolated` (no origin allowlist: it would block the app's own API on another port, CDNs and sign-in pages), an 18-tool allowlist without `browser_run_code_unsafe` (it ran Node and wrote files outside the Codex sandbox in a live test) and `browser_file_upload`. Needs Node.js; the first `npx` run downloads it.
- Ready means on PATH (or `FACTORY_CODEX` / `FACTORY_CLAUDE`) and logged in (`codex login status`, `claude auth status`). None ready, no `npx`, or a URL that is not local (`localhost`, `*.localhost`, `*.test`, `127.0.0.0/8`, `::1`; `FACTORY_ROAST_ANY_HOST=1` allows others, an env prefix no allow rule matches), or one holding `\`, quotes or whitespace: `SKIP`. Each login check is capped at 10 s.
- The agent runs in a new temp folder (never reused, owner-only on Unix), never the project: inside one it loads that project's rules and hooks (a live Claude run answered the factory's own Stop hook instead of reporting). `--restricted` keeps the owner's settings, plugins and hooks out; host session variables (`CLAUDE*`, `CODEX_*`) are dropped except the login ones: `CODEX_HOME`, `CODEX_API_KEY`, `CLAUDE_CONFIG_DIR`, `CLAUDE_CODE_OAUTH_TOKEN`, `CLAUDE_CODE_USE_BEDROCK`, `CLAUDE_CODE_USE_VERTEX`; the login check runs with the same env. Its regular files are copied to the report folder after; symlinks are skipped.
- Cap: `FACTORY_ROAST_SECS` (600) kills the whole process tree. No `VERDICT:` line, an error or the cap: `INCOMPLETE`, exit 1, never a clean pass. `--cli codex|claude` forces one. `FACTORY_ROAST=0` turns it off. A bad `FACTORY_ROAST_SECS` or `FACTORY_ROAST_SLOTS` value is a `SKIP` that names it, never a silent default.
- Waiting costs no turns: the call holds until its line. Run it as a background job, or give the call a tool timeout above the cap (Claude Code's default is 120 s). On Windows the agent's processes are killed when it exits too, and none inherits the host's output pipes, so a browser left open never holds the call.
- Machine queue: at most `FACTORY_ROAST_SLOTS` (2) roasts run at once across every session on the machine (`factory queue`, name `roast`); the rest wait inside the call, the cap starting when theirs does.
- Reuse: a finished roast is written to `<out>/roast.txt` with the working-copy tree it tested. The same URL and out folder on the same tree prints the old line with `(reused: same tree)`. With `--inert <glob>` (repeatable, the same rules as receipts: `docs/**`, `*.md`), a tree whose change from that one touches only those paths prints `(reused: <n> inert paths changed since tree <id>)`; Git decides, never an agent. `INCOMPLETE` is never reused. `FACTORY_ROAST_FRESH=1` runs it again.
- Codex host: its sandbox has no network for `claude`; `tools/night/codex.rules` allows `factory roast` outside it, else approve it once. Live: Claude host to Codex 99 s on a fixture page; Codex host to Claude was run from a Claude Code shell with `CODEX_THREAD_ID` set, not from a real Codex session.

## Other agents

| Agent | Skills | Hooks |
|---|---|---|
| Cursor | plugin, root `.agents/` (`.cursor-plugin/plugin.json`: skills, agents), install and update: [install](install.md#cursor) | runs `hooks/cursor.json`, named by its manifest (fills in `${CLAUDE_PLUGIN_ROOT}`; Windows: in PowerShell; Stop hooks run from the workspace root), and Claude Code's installed plugins too, whose hook file has no Stop: install this one and turn that import off |
| GitHub Copilot, Gemini CLI, OpenCode | read `.agents/skills` | none wired: apply the run-file rules by hand |
| Anything else | point it at `.agents/skills/safe-factory/SKILL.md` | none |

Guard live: step 1 finds `.factory/guard/state` (hooks added mid-session never load). Not live on a host with hooks: the run moves to a fresh session with `safe-factory Resume <run folder>`; still not live there (hooks not trusted, Git Bash missing): `Waiting: owner:` with the cause. On a host without hooks, Fast chains steps in one turn, one block message per step, never waits and never ends a turn with the run open and `Waiting: none`; Safe ends each step with `Say go for step <n>`. Each step still rereads `.factory/run.md` and loads the `Next:` skill fresh; checker gates and PR review still apply.

## Portable review evidence

`factory review gate-a [--skills <dir>] [--proof-inputs <json>]` runs the form check and prints a brief with the exact HEAD, the installed contracts, the local ticket when present, and the run through Plan. Copy labelled criteria from the ticket into Step 0 and list caller paths in backticks in Analyze. An optional proof manifest maps each proof ID to a list of checkout-relative paths. List those paths in backticks in the matching Plan row, even when the run will generate the files later. Save the brief as UTF-8 and give it to a fresh read-only checker. The checker still decides Gate A.

A native coded run records step starts in `.factory/guard/steps.jsonl` as UTC timestamps and step IDs. Run `factory guard begin` after creating the header for the first step. The guard records later starts as it advances. The records work with any host and contain neither message text nor tool input.

The same `factory review packet` and `factory review check` commands work in any shell that can launch the Factory binary. In a desktop or CLI session, save the packet from stdout, attach it or give its path to the reviewer, and save the returned handback as a text file. A host with no workspace read access can receive the packet as text. Use the owner's model and role policy when starting independent reviews. These commands do not need host APIs, launch a model, or replace gate backing and receipt checks.

`factory review packet --base <sha> --head <sha> [--context <tracked-file>]... [--proof <.factory-file>]...` reads committed Git text, the run through Build, the local ticket if present, and the named proof. Both commit IDs are full SHAs. For a tracker ticket, include its criteria in the Ticket block or pass a saved snapshot with `--proof`. Binary changes are described by Git and may need a separate attachment. Include only proof intended for the review. Send later receipts and proof on the same head as they arrive.

Use `factory review check --role final --head <sha> --report <full-report> <handback>` for the final reviewer or `factory review check --role checker --head <sha> --gate <A|B|C> <handback>` for a checker. Keep the complete checker handback when a host appends a short follow-up; a failure needs the missing criterion and reason, not just a count. Use `--role deep` for an aggregate deep review with a head-bound verdict. Individual lens handbacks keep their usual format. A well-formed failure still carries a failure verdict.
