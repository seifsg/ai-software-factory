# Hosts

Contents: first-class hosts · delegation · other agents · sources

Methods are host-neutral. This page = what differs per agent: where skills live, how a step loads its skill fresh, how hooks are wired, how delegates get their model.

## First-class hosts

| | Claude Code | Codex |
|---|---|---|
| Install | plugin, root `.agents/` ([install](install.md#claude-code)) | plugin, root `.agents/`, or copied skills + `~/.codex/hooks.json` ([install](install.md#codex)) |
| Invoke | `/safe-factory …` | `$safe-factory …` |
| Update | `claude plugin update safe-factory@ai-software-factory` | `codex plugin marketplace upgrade ai-software-factory` |
| Load a step's skill fresh | the Skill tool, `safe-factory:<name>` | `$<name>`, or read its `SKILL.md` |
| What compaction keeps | the first 5k tokens of each recently used skill, 25k in total; CLAUDE.md is re-read | AGENTS.md and the skill list; skill bodies are dropped |
| Stop guard | Two `prompt` Stop hooks in the `stop-check` skill's frontmatter, which the method loads right before each block or `T<n> pre:` line; other sessions start nothing. One sends the agent on only when that line's number opened no other message, so any other message ends the turn, a repeated number too. One judges a gate line no other reply has: no backing, run the delegate; backed, run the check. A block by either wins, and a repeated line gets no second block. Split because one sentence holding both tests judged worse. Any stop a hook allows removes that hook, a wait's status line too (debug log `Removed session hook` on 2.1.309; the docs say nothing of it), so a load at step start can be gone by the block; the next load adds it again. A process resume loses it too. The gate hook judges from the conversation the host gives it; no script reads a transcript, so there is no check that blocks reached chat and no relay after compactions. Loading it and running the check each need permission: an allow rule, auto mode or the owner's yes | `Stop` hook in `hooks/portable.json`, which the manifest names and which replaces `hooks/hooks.json`; runs in every session; trust once in `/hooks`; no block check (other transcript format) |
| Token limit | Tool calls reset the host's 8-block cap, and a prompt hook cannot count. A small model reads the line, so the limit is very likely, not certain. Tested on 2.1.309, Haiku and Sonnet, 6 runs per case, agents told to ignore `check` (same heading, heading cycle, todo retry): 36 of 36 ended below `--max-turns 40`, Haiku in 2 to 17 turns, Sonnet in 4 to 15, each on a hook `ok: true`. A repeated gate line, 12 runs: none reached it, 2 to 11 turns. Six todos finished 76 of 84: the hook can read a new line as already used and end the run: say go on. Real Safe runs, Sonnet, 12: all 12 ended at `Waiting: owner`, none at `Waiting: none`; 6 were seeded to hit the check's `Batched` reply and went on. Forged gate lines passed the hook 3 of 17 with a `may stop` line, 1 of 14 without, so one can reach a review; backed lines and messages with none passed 18 of 18. The run audit checks each gate line's backing: fresh reviewers flagged a swapped checker id, a forged cap and a forged waiver, 1 run each, and passed a real run. Not tested: a forged line citing a real checker's PASS on other work; Opus; Fast mode in a real run. A number the agent invents each turn is bounded only by `check`'s idle halt, if it runs; a compaction may hide a number already used (untested). `/goal` is a separate host feature that this hook does not bound: its docs advise a turn clause in the condition, such as `or stop after 20 turns`. A limit no model decides needs a command hook: `tools/night`. Always: Esc; `--max-turns` with `-p` | none needed: the command guard counts idle turns |
| Compact hook | none: the next block or todo line sends the place, and loads `stop-check` first | `SessionStart`, matcher `compact\|resume`; stdout becomes developer context |
| Guard output | `{"decision":"block","reason":…}`: the next step's prompt; Claude Code overrides after 8 blocks in a row, a count every tool call resets, so one step per turn never reaches it | same JSON; each reason becomes a user-role hook prompt and each phase has its own final response. Codex groups these rounds under one outer native turn ID |
| Fresh-context delegate | Agent tool with a plugin role | `spawn_agent` with `fork_turns: "none"` |
| Checker | `safe-factory:checker` | `spawn_agent`, `fork_turns: "none"`, `reasoning_effort: "low"`, message = the [checker](../.agents/skills/safe-factory/references/checker.md) brief plus `.agents/agents/checker.md`'s body |
| Live preview and captures | the desktop app's browser pane (`preview_start`, `.claude/launch.json`, then show the browser pane so the owner sees it) keeps the dev server the owner watches and takes every screenshot; the agent and the owner see them in chat, but the pane saves no file, so the PR carries `pane:` observations instead of image files | the browser or screenshot tool the session has |
| Background jobs | background subagents report back in a later turn: set `Waiting: jobs: … (max <n> min)` first; the guard also lets the stop through when the Stop input's `background_tasks` lists a running subagent (a background shell such as a dev server does not count), until the deadline | subagent results arrive in the parent: set `Waiting: jobs: … (max <n> min)` while they run |
| Gate and review proof | Plain runs: the Stop hook judges gate lines from the conversation, `check` tests only that a gate line exists in order, and Gate C and the review on the pushed HEAD; caps and Gate A and B commits are not tested; no script reads a transcript, so the review's run audit reads `<session>/subagents/agent-<id>.jsonl` for each checker id and `<session>.jsonl` for owner messages; the session folder is named for the run's workspace path. Night runs, with the command guard: `transcript_path` → `<session>/subagents/agent-<id>.jsonl` for every session of the run, oldest first: first line the brief (`Role: checker. Gate X` or `Role: reviewer`), its own last handback the verdict | no per-agent file: the id must appear in `transcript_path` (never accepted for a Claude Code transcript); the handback text is not checked (weaker) |
| Night session | `claude -p --permission-mode dontAsk --settings <clone>/tools/night/claude-settings.json, guard path filled in "/safe-factory Resume <dir>"` (live: denied commands fail without a prompt, allowed ones run) | `codex exec -s workspace-write -c 'approval_policy="never"' "$safe-factory Resume <dir>"` (live on Windows: flags accepted, no prompt, but the sandboxed exec helper ran nothing, so `night.sh` first runs one sandboxed command and refuses when it does not run) |
| Deny rules | `claude-settings.json` `permissions.deny` (Bash prefixes, `Edit` paths); a command hidden in `sh -c` or a script escapes them | `~/.codex/rules/factory.rules` `prefix_rule(..., decision = "forbidden")`: leading arguments only |
| Watchdog resume | `claude -p -r <session> --permission-mode dontAsk --settings <template> "<prompt>"` | `codex exec resume -c 'approval_policy="never"' -c 'sandbox_mode="workspace-write"' <session> "<prompt>"` (not yet run live) |

Every host runs `run-guard.sh` through a POSIX `sh`; on Windows that is Git Bash. `portable.json` commands start with `git --git-dir=/nonexistent -c alias…` (Git's `sh`, `GIT_DIR` unset, exit 0 always), so a host that runs them in PowerShell (Cursor on Windows) still reaches Git's `sh`. Codex can launch hook commands in PowerShell or cmd, so its `commandWindows` entries use `.agents/hooks/windows.cmd` to locate Git Bash beside `git.exe` on `PATH` and preserve native stdin/stdout. Missing Git Bash prints an actionable notice without continuing the factory. Finds the run in order: the session file `${XDG_CACHE_HOME:-~/.cache}/ai-software-factory/sessions/<session id>`, nearest `.factory/run.md` inside session's checkout (walking up from the hook input's `cwd`, else the hook's own directory: a desktop worktree session's hook may start elsewhere), then the `**Workspace:**` path of a step block opening the turn's last message. A step block naming a run rebinds first. A desktop worktree session cannot change folder, so its run often lives elsewhere; a step block with no findable run blocks once and asks, then warns the owner. A stopped or finished run deletes its session file; files over 30 days go at the next bind. A worktree's run stays separate from its parent's. Also reads that session's subagent files and, on Claude Code, the run's session transcripts (posted step blocks). State: `.factory/guard/state` (single-quoted `g_*` lines; anything else reported and ignored). Ignores runs untouched for 12 hours. Only `Waiting: owner:` or `jobs:` stops a run; any other spelling is driven and told the exact header. Past step 3 it names a step not ticked; at any step it refuses a run file line over 300 characters outside tables and fences; neither finishes. A finish it saw holds while the run says `Status: closed`, wherever HEAD went; `closed` alone proves nothing. No remote, ever: `HEAD` counts as pushed. On Windows, paths reach the agent through `cygpath -m`. Runs once per turn end, never per tool call. `night.sh` and `watchdog.sh` in `tools/night/` call the host CLIs above; `FACTORY_CLAUDE` and `FACTORY_CODEX` name a CLI off PATH (desktop installs), `FACTORY_START`, `FACTORY_RESUME`, `FACTORY_FRESH` and `FACTORY_NOTIFY` replace the commands, `FACTORY_IDLE_TURNS` (6) and `FACTORY_JOB_MAX` (120 min) tune the guard.

## Delegation

Roles (runner, analyst, maker, builder, reviewer, checker), their tiers and brief, gate and handback rules live in `.agents/skills/safe-factory/references/delegate.md`. Hosts differ only in how a role gets model, effort and edit limits. Owner's own session model and effort never change.

Pass request, decisions, interfaces, stops and artifact paths explicitly; full history needs a reason. Keep short jobs local.

| | Claude Code | Codex |
|---|---|---|
| Roles | plugin agents `safe-factory:<role>` from `.agents/agents/`; when missing, a general-purpose agent with the tier's `model` and `effort`, told to stay read-only where the role is | none shipped: the brief names its role |
| Tier models, light / standard / deep | `haiku` low / `sonnet` medium / `opus` high, pinned in each agent file | the spawn asks for effort `low` / `medium` / `high`; the model stays the parent's unless the owner sets one |
| Read-only roles | a `tools` allowlist without write tools; shell writes barred by instruction | by instruction only |
| Session ceiling | a role above the session's tier runs on the session's model | the parent's model, unless the owner sets one |
| Owner override | per-call `model` and `effort`; `CLAUDE_CODE_SUBAGENT_MODEL` with `CLAUDE_CODE_SUBAGENT_MODEL_FORCE=1`; `CLAUDE_CODE_EFFORT_LEVEL` | an agent file in `~/.codex/agents/` or `.codex/agents/` named for the role, with `model` and `model_reasoning_effort` |

## Other agents

| Agent | Skills | Hooks |
|---|---|---|
| Cursor | plugin, root `.agents/` (`.cursor-plugin/plugin.json`: skills, agents), install and update: [install](install.md#cursor) | runs `hooks/portable.json`, named by its manifest (fills in `${CLAUDE_PLUGIN_ROOT}`; Windows: in PowerShell), and Claude Code's installed plugins too, whose hook file has no Stop: install this one and turn that import off |
| GitHub Copilot, Gemini CLI, OpenCode | read `.agents/skills` | none wired: apply the run-file rules by hand |
| Anything else | point it at `.agents/skills/safe-factory/SKILL.md` | none |

Guard live: step 1 finds `.factory/guard/state` (hooks added mid-session never load). Not live on a host with hooks: the run moves to a fresh session with `safe-factory Resume <run folder>`; still not live there (hooks not trusted, Git Bash missing): `Waiting: owner:` with the cause. On a host without hooks, Fast chains steps in one turn, one block message per step, never waits and never ends a turn with the run open and `Waiting: none`; Safe ends each step with `Say go for step <n>`. Each step still rereads `.factory/run.md` and loads the `Next:` skill fresh; checker gates and PR review still apply.
