Architecture map, not live run status. Seif's methods and deliberate reminders remain; project assumptions are generalized. The local controller's five acceptance passes are separate from four-theme PR review. Games, apps, services and tools research product/UX and technical choices, then plan safe logs, CPU/GPU, memory, data access and useful caching; existing changes address affected gaps with focused evidence. Ticketing preserves owner-confirmed before/after scope and activity. Every new ticket gets a dedicated full-cycle session; shared epic checkouts are serial. Legacy unticketed small fixes retain the lighter route. Every complete outcome ticket is an iteration; whole-product acceptance stays open. Small fixes stay surgical: finish implementation, exercise it manually, then write/polish/run automated tests at the final pre-PR stage and obtain the applicable independent review. No automated tests during development. Broader checks are offered when useful and run when requested or genuinely required. Version checkpoints keep the full QA method. Fast and Lucky runs keep tickets, recorded methods and the product bar; the Claude Code plugin's hooks call the Fast gate. This is an agent-operated workflow, not a background service; a small-change handoff does not certify an entire version or prove a speedup.
